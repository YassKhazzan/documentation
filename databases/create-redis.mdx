Create a Redis 8 database for caches, queues, sessions and pub/sub. Redis keeps its data in memory, so the main choices are how much memory it gets and what it does when that memory is full.

## Before you start

- A server in the workspace that reads **Connected**, with free memory for the size you choose.
- Room in your plan: 3 databases on Free, 30 on Pro, 100 on Teams, PostgreSQL and Redis counted together. See [Plans](/account/plans).
- The role **Owner**, **Admin** or **Developer**.

## Steps

<Steps>
  <Step title="Open the form">
    Open **Databases** and press **Create database**, then pick **Redis**. Or press **New** at the top of the console and choose **Redis database**. The form title becomes **Create Redis**.
  </Step>
  <Step title="Name it and pick a server">
    Fill in **Database name** (2 to 120 characters, for example `shop-cache`) and choose the **Server**.
  </Step>
  <Step title="Choose the size">
    Under **Size**, choose **Memory for data**, **CPU** and **Max connections**. See the tables below.
  </Step>
  <Step title="Choose what happens when memory is full">
    Under **When memory is full**, keep **Keep everything** or choose **Cache**.
  </Step>
  <Step title="Create it">
    Press **Create Redis database**. The console opens the new database's page.
  </Step>
</Steps>

## Memory

**Memory for data** is the most data Redis holds. Redis also needs room to save its data to disk, so the server gives it more than the data size. LiveHQ sets the disk budget from the memory: four times the memory, and at least 1 GB.

| Memory for data | The most it may use on the server | Disk budget |
| --- | --- | --- |
| 128 MB | 192 MB | 1 GB |
| 256 MB (default) | 384 MB | 1 GB |
| 512 MB | 768 MB | 2 GB |
| 1 GB | 1.5 GB | 4 GB |
| 2 GB | 3 GB | 8 GB |
| 4 GB | 6 GB | 16 GB |

The disk budget is monitored, not reserved: it is the figure the **Append-only file** meter on Overview compares against. A backup may be at most twice the disk budget.

**CPU** is 0.5, 1 (default), 2 or 4 CPU. Redis runs commands on one thread; 2 CPU or more adds I/O threads. **Max connections** is 1,000 by default, from 100 to 10,000. See [CPU, memory and connection limits](/databases/sizes-and-limits).

## When memory is full

| Choice | What Redis does | Use it for |
| --- | --- | --- |
| **Keep everything** (default) | Writes fail when memory is full. Nothing is removed. | Queues, sessions and data you can't lose. |
| **Cache** | Evicts the least recently used keys to make room. | A cache your app can rebuild. |
| **Advanced eviction policies** | Opens **Eviction policy**, a list of six Redis policies. | When you know which Redis policy you need. |

The six advanced policies are `allkeys-lfu`, `volatile-lru`, `volatile-lfu`, `volatile-ttl`, `allkeys-random` and `volatile-random`. The list says what each one evicts.

<Warning>
With **Cache** or any eviction policy, Redis deletes keys on its own when memory is full. Do not use it for a job queue or for sessions you cannot lose.
</Warning>

## How Redis keeps your data

Redis writes every change to a file on your server's disk (the append-only file) once a second. A restart of Redis or of the server brings all keys back. If the server crashes, up to about a second of writes can be lost.

That file is not a backup: it is on the same disk as the database. See [Back up a database](/databases/backups).

## What happens next

The status reads **Provisioning**, then **Ready**. You get a default user named `livehq` with a generated password (**Reveal password** on the **Users** tab shows it again at any time), sixteen Redis databases (`db0` to `db15`; connection URLs use `db0`) and the JSON data type alongside Redis's own. There is no public address and no backup yet.

Next, [connect an app](/databases/connect-an-app) or open [Redis Studio](/databases/redis-studio).

## Change memory or the full-memory rule later

- **Memory, CPU, connections:** open the database, then **Settings**, then **Change size**.
- **When memory is full:** in **Settings**, choose again and press **Save and restart Redis**.

Both restart Redis for a few seconds while it reloads its data. Apps are disconnected briefly and reconnect on their own. Keys are kept. Before you lower the memory, check the **Memory** figure on Overview: the data must fit the new size.

## If something goes wrong

| What you see | What it means | What to do |
| --- | --- | --- |
| The server is greyed out with **Agent update required** | The agent on that server is too old to run Redis. | If the console says **Update this server's agent**, see [Update the agent](/servers/update-agent). |
| A size cannot be chosen, with a reason such as "More than the server's 2 cores" | The server cannot give Redis that much. | Choose a smaller size. |
| The status reads **Failed** after creating | Setup did not finish. **Recent operations** on Overview shows the server's reason. | Fix the cause, then press **Retry setup** in the **Lifecycle** card and **Confirm**. |
| Your app's writes fail with an out-of-memory error from Redis | Memory is full and the rule is **Keep everything**. | Delete keys you no longer need, raise **Memory for data**, or switch to **Cache** if the data can be rebuilt. |
| Keys disappear | The rule is **Cache** or an eviction policy, and memory was full. Or the keys had an expiry. | Raise the memory, or use **Keep everything**. Redis Studio's **Insights** shows how many keys were evicted. |

## Limits

- One Redis server per database. There is no cluster, no replica and no failover.
- Only the JSON module is loaded. Search, time series and the other Redis modules are not available.
- Memory for data goes up to 4 GB.
