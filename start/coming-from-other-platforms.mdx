If you have deployed on another platform, most of LiveHQ will feel familiar: connect a repository, push, get an address with HTTPS. This page maps the ideas and names what is different, so nothing surprises you later.

## The one big difference

On LiveHQ **the server is yours**. You rent it from a hosting company, and LiveHQ builds and runs your apps on it. Two things follow:

- **Capacity is your server's.** Memory and CPU limits are caps you set inside your own server. There is no per-app or per-build pricing: you pay the hosting company for the server and LiveHQ for the [plan](/account/plans).
- **Builds run on your server too.** A big build shares memory with your running apps. See [How memory is shared](/servers/memory).

Compared with running everything yourself, LiveHQ's control plane is hosted: nothing but a small agent and Docker runs on your server, and the server opens no web ports. Visitors arrive through LiveHQ's edge.

## What works differently

- **Apps are long-running containers.** There are no serverless or edge functions. A Next.js app runs as a Node server, and API routes run inside it.
- **One deployment at a time per server.** A second deployment waits for the first.
- **No preview deployments per branch or pull request.** An app follows one branch. To preview another branch, deploy it as a second app.
- **One set of variables per app.** There are no separate production, preview and development sets.
- **No configuration file in the repository.** Settings live in the console. There is nothing like `vercel.json`, `render.yaml` or a Compose file to deploy from. The exception is your own `Dockerfile`.
- **Bare domains cannot be served.** Use `www.example.com` and redirect `example.com` to it at your domain company. See [Custom domains](/apps/custom-domains).
- **Your server is patched for you.** LiveHQ installs security updates and may restart the server at a planned weekly time. See [Security updates and restarts](/servers/system-updates).

## What LiveHQ does not have

Scheduled jobs (cron), autoscaling, persistent volumes for apps, raw TCP or UDP services, names for one app to call another, a public API, a command-line tool, and point-in-time recovery for databases. The full list, with what to do instead, is on [Known limits](/help/known-limits).

## If you ran your own server before

- Remove nothing first. The installer reuses a healthy Docker installation and leaves your existing containers alone. See [What server you need](/servers/requirements).
- You do not need a reverse proxy, a certificate tool or open ports 80 and 443 for LiveHQ apps. After moving your apps you can [close the server](/servers/lock-down).
- SSH stays yours. LiveHQ never holds or adds an SSH key. [Private SSH](/servers/private-ssh) lets you reach the server with every port closed.
